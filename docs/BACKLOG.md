# Backlog

Known limitations, technical debt and future features that are **not** implemented. Sources: PR #1 review items 6-9 and 11, the independent branch reviews, and the Milestone 1 work (checked against the code on 2026-11-22). Priority and scope are not decided; entries describe the current state only. Architectural decisions are recorded separately in `DECISIONS.md`.

| # | Type | Item | Current state |
|---|---|---|---|
| 6 | Technical debt | Browser-clock guard is a source scan, not a lint rule | `frontend/src/features/attendance/noBrowserClock.test.ts` fails on `Date.now()`, `new Date()` and `performance.now()` in app sources. oxlint has no matching rule, and the regex would miss forms such as `Date['now']()`. |
| 7 | Technical debt | No component tests for two admin screens | `AttendanceAdmin.tsx` and `ShiftSettings.tsx` have no component tests. Covered today: `Employees.tsx` and `WeekdayDurations.tsx` (own tests), the timesheet and the edit/delete dialogs, the correction dialog, the clock panel, the punch logic, the invite link, and the backend endpoints these screens call. |
| 8 | Limitation | time.now attribution not added | time.now's page asks for attribution when using its free API. Nothing is shown in the app or README. It also publishes no numeric rate limit (a punch makes 1 request, at most 4). |
| 9 | Limitation | Corrections are minute-granular | Both the admin correction form and the employee shift dialog take minutes only, so a shift cannot be closed within the minute it started (the server answers "Clock-out must be after clock-in"). |
| 11 | Future feature | Idempotency keys for clock requests | Not built. A retry after a lost response gets a 409; the UI explains it using `/status`. |
| 11 | Future feature | Change-password endpoint | Not built. A forgotten or replaced password needs a new invite link from an admin. |
| 11 | Future feature | Anomaly flagging for forgotten clock-outs | Not built. An open record stays open until the employee clocks out (or the admin corrects it); nothing flags it. Built since: a clock-out on a later date shows "needs correction" and is not counted, and employees can fix their own days from the timesheet. |
| 11 | Future feature | Month picker | Not built. The employee timesheet and the admin attendance view have previous/next month buttons only. |

| F8 | Limitation | No UI to change an employee's schedule or see its history (Iteration 1.2) | The backend `POST/GET /admin/employees/{id}/schedule` appends and lists schedule versions (effective date on or after the first of the current Zurich month), but `Employees.tsx` only sends a schedule on creation.
